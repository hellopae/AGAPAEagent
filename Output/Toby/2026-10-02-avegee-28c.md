## สาเหตุเสียงแตก (วัดจริง ไม่ได้เดา)
ดัก event ของ `<audio>` ใน Chromium จริง (Playwright) สลับ zone <-> battle 10 รอบ ได้ว่า

- **ไม่ใช่เสียงซ้อน/context ซ้ำ** — มี `<audio>` 1 ตัวและ `AudioContext` 1 ตัวตลอด
- **ไม่ใช่ไฟล์เพลงแตก** — `ffmpeg astats` ทั้ง 3 ไฟล์: peak -2.9 / -0.8 / -0.3 dB, flat factor 0, ไม่มี clipping
- **ไม่ใช่ gain เกิน 1.0** — ผลรวมสูงสุดเพลง (0.22 x peak 0.67) + เอฟเฟกต์ ~0.6
- **สาเหตุจริง:** `sfx.js` เดิมใช้ `<audio>` ตัวเดียวแล้ว **เปลี่ยน `el.src` ทุกครั้งที่เปลี่ยนเพลง**
  - ทุกสลับ (20/20 ครั้ง) เกิดลำดับ `abort -> emptied -> waiting -> loadstart -> canplay` = รื้อ pipeline แล้วโหลดไฟล์ใหม่ทั้งไฟล์ ตรงจังหวะที่หน้าจอกำลังวาดฉากต่อสู้ (รูปใหญ่ + คัตซีน)
  - เซิร์ฟเวอร์ dev (`serve-nocache.py` / `python -m http.server`) ไม่รองรับ Range และสั่ง no-store -> ดึง 2.6 MB ใหม่ทุกรอบ, `warmBgmFile` (fetch อุ่น cache) ไม่เคยช่วย
  - ตัดเพลงเก่ากลางคลื่น + เพลงใหม่เริ่มที่ความดังเต็มทันที (ไม่มี fade) = คลิก/ป๊อปที่รอยต่อ
  - เพลงโซนเด้งกลับ 0:00 ทุกครั้งที่สู้จบ
- **ข้อจำกัดที่ต้องบอกตรง ๆ:** ผมฟังเสียงไม่ได้ — หลักฐานคือ event log + ค่า volume ไม่ใช่ได้ยินเอง "สะดุดจริง" บนมือถือ Kittanate ควรฟังยืนยัน (ดูวิธีทดสอบ)

## สิ่งที่ build
- เพลงทุกเพลงมี `<audio>` ของตัวเอง **สร้างครั้งเดียว ตั้ง src ครั้งเดียว** สลับด้วย crossfade 700 ms (ผลรวมความดัง <= `AUDIO.bgm`, clamp 0..1 กัน `RangeError` จากค่า localStorage เสีย)

## สิ่งที่ยังไม่ทำ
- ไม่มี SFX เสียงยมทูตช่วย/ยักษ์ แยกรายตัว (ยังใช้ `hit`) และไม่มีเสียงท่าไม้ตายของบอสฝั่งศัตรู (`nb.ultimate` ยังใช้ `hurt`) — ไม่อยู่ในใบงาน

- ไม่ได้แก้ `serve-nocache.py` ให้รองรับ Range (ทำให้ dev server ต่างจาก GitHub Pages) — ถ้าอยากให้ทดสอบเหมือนของจริง แจ้งได้

## ประสิทธิภาพ (fps) — ตัวเลขจริงและข้อจำกัด

วัดใน Chromium headless (ไม่มี GPU = raster ด้วย CPU) DPR2 390×844 — **ไม่ใช่เครื่องจริง**:
- เฟรมที่เอฟเฟกต์ทำงาน: ลูกไฟ/ฟัน/น้ำแข็ง/ลม 3 ศัตรู เฉลี่ย **17–22 ms/เฟรม (~45–60 fps)** · งาน JS ของเอนจินเองเฉลี่ย 2–5 ms/เฟรม (สูงสุด ~19 ms ตอนน้ำแข็ง 3 ศัตรูพร้อมกัน) · อนุภาคสูงสุดที่เห็น 98 (เพดาน 300)
- **หลัง ~4–5 ท่าติด ที่มีภาพคั่นเต็มจอ เฟรมช้าลงเป็น ~45–55 ms** — **main เดิมที่ไม่มีโค้ด M2 ก็เป็นแบบเดียวกัน** (วัดเทียบด้วย rAF ฝั่งหน้าเว็บ ลำดับท่าเดียวกัน: main หลังท่าที่ 3–5 เฉลี่ย 40–47 ms · M2 47–69 ms — ช่วงนี้ M2 ช้ากว่า main ราว 5–20 ms ตามที่คาด เพราะเพิ่มงาน canvas บนเครื่องที่ไม่มี GPU) ต้นเหตุน่าจะอยู่ที่ภาพคั่น/คอมโพสิตของหน้าต่างศึกเดิม ไม่ใช่ M2 · **ยังไม่ได้ลองบนมือถือจริงและ Safari/iOS** — ถ้าเครื่องจริงช้าเอนจินลดความละเอียด canvas ให้เอง
- ตัวสั่นจอเดิมที่เป็นต้นเหตุเฟรมช้า (CSS translate ทั้งกล่อง → repaint ทั้งฉาก) ผมแก้ให้ใช้ชั้นคอมโพสิตของตัวเองระหว่างสั่น (`will-change: translate`) เฟรมน้ำแข็ง/ลมจาก ~32–57 ms เหลือ ~19–20 ms · พอ merge กล้อง M1 การสั่นจะเป็นของกล้อง

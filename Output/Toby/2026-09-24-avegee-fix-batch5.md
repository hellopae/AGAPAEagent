### A — หน้าสอบสวน: เลือกข้อหนึ่งแล้วข้ออื่นหาย → แก้แล้ว
**ต้นเหตุจริง (ยืนยันด้วย log ชั่วคราวแล้วลบออก):** วงคำสั่ง (`command-wheel.js`) ผูกทั้ง
`pointerenter` (hover เปิดพรีวิวสำหรับจอมีเมาส์) และ `onclick` (สลับเปิด/ปิดตาม
`aria-expanded` ปัจจุบัน) ไว้ที่ปุ่มเดียวกัน คลิกจริงทุกครั้งเมาส์ต้องเข้าไปแตะปุ่มก่อน
เสมอ → เบราว์เซอร์ยิง `pointerenter` (เปิดวง false→true) ตามด้วย `click` ทันทีในคลิก
เดียวกัน ซึ่งอ่านค่า `aria-expanded` ที่เพิ่ง hover เปิดไปแล้ว ตีความว่า "ผู้ใช้ต้องการ
ปิด" แล้วสลับปิดคืนทันที — วงกะพริบเปิดแล้วปิดเองทุกคลิก เลือกอะไรแทบไม่ติด
(reproduce ได้ชัดด้วย Playwright: คลิกวงครั้งเดียว `aria-expanded` จบที่ `false` เสมอ)

ผลพวง: ยังมี CSS เดิม `.has-options .command-selected{opacity:0}` ที่ซ่อนป้าย
"เลือกแล้ว" ทั้ง 3 ป้ายทุกครั้งที่วงไหนก็ตามเปิดอยู่ (ไม่ใช่แค่ป้ายของวงที่เพิ่งเปิด)
ทำให้ดูเหมือนตัวเลือกของอีกสองข้อหายไปทุกครั้งที่ไปเปิดวงถัดไป ทั้งที่ `pick.st` /
`pick.cr` / `pick.inten` ใน `ui.js` ไม่เคยถูกล้างค่าเลย (ตรวจโค้ดแล้ว ไม่มี logic bug
ตรงนั้น)

**วิธีแก้:** แยกพฤติกรรมคลิกด้วย `matchMedia('(hover:hover) and (pointer:fine)')` —
จอมีเมาส์จริง คลิกแค่ "ตรึงให้เปิดอยู่" ไม่สลับปิดเอง (ปิดได้ด้วยย้ายไปวงอื่น/Esc/ปิด
กล่อง) ส่วนจอทัช/คีย์บอร์ด (ไม่มี hover) คลิกสลับเปิด-ปิดเหมือนเดิม เพราะไม่มี hover
เปิดล่วงหน้าให้เกิด race · และเปลี่ยน CSS `.has-options` (ซ่อนทั้งหมด) เป็น
`:has()` เจาะจงซ่อนเฉพาะป้ายของวงที่กำลังเปิดอยู่จริง

### B — กด "ออกหมาย" ไม่ได้ → แก้แล้ว
**ต้นเหตุ:** อยู่ที่ข้อ A ทั้งหมด — เพราะวงกะพริบเปิด/ปิดเอง ตัวเลือกที่ผู้เล่นเข้าใจว่า
กดแล้วจึง "ครบ" ในสายตา แต่บางช่องยังเป็น `null` จริง ๆ `ready` เลยเป็น `false`
ตรวจโค้ดเงื่อนไข `ready`/`doVerdict` แล้วไม่มีจุดไหนคำนวณผิด — ยืนยันด้วย Playwright:
ตั้งค่า `pick` ครบทั้ง 3 ช่องจริง ๆ แล้ว `#t-go` เปิดใช้งานได้ปกติทันที

**ส่วนที่เป็นบั๊ก B โดยตรง:** ปุ่มที่มี `disabled` attribute จริงจะไม่ยิง `click` event
และไม่โชว์ `title` tooltip บนจอสัมผัสเลย — กดแล้ว "เงียบ" ไม่มีทางรู้ว่าขาดอะไร

**วิธีแก้:** คำนวณ `missingParts` (ที่ไหน/ใครคุม/ความแรง ที่ยังไม่ได้เลือก) ทุกครั้งที่
`paint()` แล้วโชว์เป็นข้อความถาวรบนจอ (ไม่ใช่ tooltip) เหนือแถวปุ่มคำสั่งคดีเมื่อยังไม่
ครบ ไม่แตะกลไกคะแนน/เงื่อนไข `ready` เดิมเลย

### C — เลือดในหน้าต่างศาลากับแถบหลักไม่ตรงกัน → แก้แล้ว
**ต้นเหตุ:** `room.js` เขียน `g.hp` ตรง ๆ ทุกเฟรมระหว่างนั่งพัก (ตั้งใจให้ฟื้นต่อได้แม้
เกมพักอยู่กับกล่องโมดัล) โดยไม่ผ่าน `g.onChange()`/`refresh()` เลย — ป้ายในหน้าต่าง
(`#st-hp-chip`) ถูกไล่แพตช์ทุกเฟรมอยู่แล้วเลยตามทัน แต่แถบหลักด้านหลัง (`#res`) วาด
จาก `refresh()` ที่ถูกเรียกเฉพาะตอนมี action อื่นผ่าน `onChange()` เท่านั้น เลยค้างค่า
เก่าจนกว่าจะมี event อื่นบังเอิญเกิดขึ้น (แสดงผลไม่ refresh — ไม่ใช่ค่าไม่ถูกเขียนลง
state จริง, การเซฟเดิมทำงานถูกอยู่แล้ว)

**วิธีแก้:** แพตช์ `#res-hp-chip` พร้อมกับ `#st-hp-chip` ทุกเฟรมระหว่างนั่ง และเรียก
`refresh()` ทันทีที่ปิดหน้าต่างศาลา กันไม่ให้แถบหลักค้างค่าเก่าไม่ว่าจะปิดจังหวะไหน

### D — ศาลาน้ำชา: ซูมเข้าไปในอาคาร → แก้แล้ว
ใช้ `img/BG-Tea.webp` เดิม ไม่ gen ภาพใหม่ — เพิ่มกลไก `room.crop = [sx,sy,sw,sh]`
(สัดส่วน 0-1 ของภาพต้นฉบับ) ใน `room.js`: ถ้าห้องไหนกำหนดไว้ จะตัดเฉพาะส่วนนั้นด้วย
`drawImage` รูปแบบ 9 อาร์กิวเมนต์แทนยัดภาพทั้งใบ แล้วคำนวณ "contain" ใหม่จากขนาด
ส่วนที่ครอปแล้ว จุดยึด (`me`/`walk`/`act`/`item`) ที่วัดเป็น 0-1 เทียบกับ box จึงใช้งาน
ถูกต้องทันทีโดยไม่ต้องแก้โค้ดส่วนอื่น

วัดกรอบครอปจริงจากภาพ (1081×976px) ได้ `[0.1286,0.1844,0.8335,0.5533]` (เห็น
หลังคา พื้นศาลา โต๊ะอาหาร คนนั่งครบ) แล้ววัดพิกัด `me`/`act`/`item`/`walk` ใหม่ให้ตรง
กับกรอบที่ครอปแล้ว ตัดทางเดินบันได/หน้าผา (poly เดิมอันแรก) ทิ้งเพราะซูมแล้วมองไม่
เห็นส่วนนั้นอีกต่อไป โซนเอเชีย (ภาพคนละไฟล์) ใส่ `crop:null` ชัด ๆ กันสืบทอดค่าไป
ครอปผิดตำแหน่ง — นอกสโคปรอบนี้ (ยังไม่มีคนสั่งแก้)

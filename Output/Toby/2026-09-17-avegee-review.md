## 3. เปิดเกมจริง — สิ่งที่ทดสอบและ console error ที่เจอ

รันด้วย `python3 -m http.server 8777` + Chrome headless ผ่าน CDP (คลิกจริงและยิง event ผ่าน `Input.dispatchMouseEvent`, ไม่ใช่แค่ประกอบ HTML อ่านตา)

**ทำสิ่งเหล่านี้จริงแล้วดู console/network:**
1. เปิดหน้าปก → ไม่มี error, ภาพหน้าปกโหลดสำเร็จ
2. กด "ดูบทนำอีกครั้ง" → เดินหน้า intro 5 หน้าเต็ม (1/5 → 5/5) ปุ่มเปลี่ยนข้อความถูกต้อง (หน้าถัดไป → กลับหน้าเมนู) ไม่มี error
3. กด "เริ่มเกมใหม่" → อินโทรเด้งอัตโนมัติ, ข้ามอินโทรได้, เจอ tutorial บทที่ 1 ทันที ไม่มี error
4. บังคับ `zoneCases.th=10` แล้วเดินผ่าน flow จริง (`bossPending`→`beginBossBridgeWalk`→เดินสะพาน→prep บอส→ต่อสู้→ชนะ→กลับแผนที่) — ครบทุกจอ ไม่มี error, `bossCleared.th` บันทึกถูกต้อง
5. เรียก `G.assign()` ให้ยมทูต (`taan`, ไม่ใช่ตัวผู้เล่น) รับคดี → เห็น `escort` ผูกกับ soul id, สร้าง `transits` มี pickup/outbound/timestamp ครบ, พอถึงเวลาส่งของสำเร็จ `transits` กลับเป็น 0 และ `escort` เป็น `null` ตามที่ควร — ไม่มี error
6. ทดสอบ viewport 390×844 และ 360×740 — ไม่มี overflow

**console error ทั้งหมดที่เจอทั้งเซสชัน (unique):**
```
[HTTP 404] img/hero-yama-side.png      — ของเดิม ตั้งใจให้ 404 (มีคอมเมนต์ในโค้ดบอกไว้ ดู CONCEPT §16)
[HTTP 404] audio/bgm-title.ogg          — fallback ไป .mp3 สำเร็จ ไม่กระทบผู้เล่น
[HTTP 404] audio/bgm-zone.ogg           — เหมือนกัน
[HTTP 404] favicon.ico                  — ไม่กระทบเกม
[HTTP 404] audio/bgm-yama.ogg/.mp3/.m4a — ไฟล์เสียงนี้ไม่มีอยู่จริงเลย (บั๊ก #2 ข้างบน)
```
ไม่พบ JS exception จาก `Runtime.exceptionThrown` ตลอดเซสชันทดสอบ ไม่พบ syntax error (`node --input-type=module --check` ผ่านทุกไฟล์ใน `src/*.js`)

**ยังไม่ได้ทดสอบ (นอก scope เวลาที่มี):** ต่อสู้บอสโซนบูรพา/ปัจฉิม (ต้องเลื่อนขั้นจริงถึงเลเวล 3/4 ก่อน ใช้เวลาเล่นยาว), การย้ายโซนจริงหลังชนะบอส (ติดเงื่อนไขเลเวลผู้เล่นในเซฟทดสอบ), เคส "ลูกทีมที่ติด" ด้วยเซฟเก่าจริง, เพลงประกอบ (ไม่ได้เปิดลำโพงเทียบเสียง เพราะไฟล์หลักไม่มีอยู่แล้ว)

## 4. ไฟล์ untracked — อันไหนต้อง commit อันไหนไม่ต้อง

**ต้อง commit ก่อน push (ถ้าจะใช้งานจริง) — แต่ตอนนี้ยังไม่กระทบเว็บที่ deploy อยู่เพราะไม่มีโค้ดอ้างถึง:**
- `img/CyberHell/crew-nira-cyberhell.png`, `img/CyberHell/hero-yama-cyberhell.png` — ตรวจแล้ว `grep` ไม่เจอชื่อไฟล์นี้ในโค้ดเลย (ดูข้อ 2 บั๊ก #3) เป็นงานเตรียมโซน 4 ที่ยังไม่ได้ต่อสาย **ไม่ commit ตอนนี้ก็ไม่พังเว็บ** แต่ถ้าไม่ commit จะหายถ้าเครื่องมีปัญหา — แนะนำให้ commit เพื่อกันของหาย ไม่ใช่เพราะเว็บต้องการ

**ไม่ควรขึ้น repo หลัก (ตรงตามนโยบายที่มีอยู่แล้วใน CONCEPT §18.3(ค)) แต่ต้องเช็คว่าเจ้าของตั้งใจเก็บไว้จริง:**
- `img/raw/**` ที่ยัง untracked ทั้งหมด (Asia/CyberHell/West/root รวม 18 ไฟล์ + 5 `intro-panel-0X.png`) — เป็นต้นฉบับก่อน `prep-art.py` แปลง ตาม convention เดิมของโปรเจกต์ (`img/raw/` **เข้า git แล้ว 105MB ก่อนหน้านี้** ดู CONCEPT §18.3(ค)) ของกลุ่มนี้ยังไม่เข้า จึง**ไม่สอดคล้องกับ convention เดิม** — ถ้าจะรักษามาตรฐานเดียวกันต้อง commit เพิ่ม (ไม่กระทบเว็บที่ deploy เพราะ `img/raw/` ไม่มีโค้ดโหลดใช้เลย เป็นแค่ที่เก็บต้นฉบับ)

## 5. ขนาดไฟล์ภาพใหม่ เทียบงบ §18.3

วัดจริง 17 ก.ย. 2569 ด้วย `git ls-files` + `du` (ไม่ใช้ตัวเลขเก่าจาก CONCEPT ที่บอกว่าใช้ไม่ได้แล้ว):

| ชุด (ข) — คลังที่ commit แล้ว ขึ้นเว็บจริง | ไฟล์ | ขนาด |
|---|---|---|
| `img/` ราก | 101 | 19.83 MB |
| `img/Asia/` | 43 | 8.10 MB |
| `img/West/` | 5 | 1.04 MB |
| `img/CyberHell/` | 1 | 0.18 MB |
| **รวม (ข) วันนี้** | **150** | **29.15 MB** |
| รวม (ข) วัดไว้ 12 ก.ย. (ฐานเทียบ) | 137 | 24.03 MB |
| **เพิ่มขึ้นในรอบนี้** | **+13** | **+5.12 MB** |

ไฟล์ใหม่หลักที่ทำให้โต: `intro-panel-01..05.webp` (5 ไฟล์ ~551 KB รวม), `zone-boss*.png` ของ 3 โซน + คีย์กลาง (~655 KB รวม), `prop-throne-platform-v1.png` (1.12 MB), `scene-foreground-v1.png` (0.78 MB), `scene-ground-v1.png` (1.45 MB) — สามไฟล์หลังนี้หนักสุด **เช็คแล้วว่าไม่มีไฟล์ชื่อไม่มี `-v1` ซ้อนอยู่ใน `img/` ราก** (`git ls-files` หาไม่เจอ `scene-foreground.png`/`scene-ground.png`/`prop-throne-platform.png` เวอร์ชันไม่มี `-v1` เลย มีแต่ต้นฉบับใน `img/raw/`) — ไม่มีไฟล์ขยะซ้ำให้ลบ

**เทียบเพดาน 50 MB:** ไม่ว่าจะตีความว่าผูกกับ (ก) ต่อเซสชัน หรือ (ข) คลังรวม เลข 29.15 MB ยังห่างเพดานพอสมควร (§18.3 ประเมินไว้ว่าทำครบ 4 โซนจะแตะ 49-51 MB ซึ่งเป็นตัวเลขที่ยังไม่รวมโซน 4 จริงจัง) — **รอบนี้ไม่มีความเสี่ยงเรื่องงบไฟล์** แต่ยังเป็นเรื่องที่ Kittanate ต้องเคาะว่าเพดานผูกกับตัวไหนตามที่ CONCEPT บันทึกไว้แล้ว (ไม่ใช่หน้าที่ Toby ตัดสิน)

## สิ่งที่คุณเป้ขอ (ถ้อยคำเดิม สรุป)
1. **ยมทูต/Guard เก่งขึ้นตามโซน** — แต่ละโซน ยมทูตและ Guard ของทีมโจมตีแรงขึ้น ใช้พลังแรงขึ้น เติมเลือดได้มากขึ้น ไปเรื่อยๆ (ศัตรูก็เก่งขึ้นตามโซนอยู่แล้ว)
2. **ระบบ level up ยมทูตผ่าน minigame ในสถานที่** (ยมทูตแต่ละตัวมี id: yama, taan, plerng, kan, boon, nira, dam, guard — ตรวจชื่อจริงในโค้ด)
   - st-dab: ฝึกฟันดาบ → เพิ่มพลังโจมตี **yama**
   - st-lan: ยกก้อนหิน → level up **taan, guard**
   - st-krata: เร่งไฟ → **plerng**
   - st-krajok: หมุนองศากระจกให้แสงส่องไปทางออกของวิหาร → **kan**
   - st-sawan: นั่งสมาธิกำหนดลมหายใจ → **boon**
   - st-sala: puzzle เรียงเอกสารแบบ Bizzler → **nira** (เพิ่ม "ระเบียบ")
   - st-ngiw: ฟันต้นงิ้ว → **dam**
   - st-lokan: ยกก้อนหิน → **guard**
3. **ร้านพ่อค้านรกขายของตามโซน** — โซน 2 มียาเติม HP/MP ที่เติมได้มากกว่าโซน 1, โซน 3/4 มากขึ้นไปอีก
4. **event สุดท้ายโซน 4 ทำใหม่**
   - สู้ศัตรูแต่ละ wave ชนะแล้ว **ได้เงิน (+ไอเทม)** มีหน้าต่างเด้งบอก เอาเงินไปซื้อของที่พ่อค้านรกได้
   - หลังชนะลูกน้องบอสโซน 4 ครบ 4 wave → **cutscene ยมทูตจากโซนต่างๆ ตามมาช่วย** (มีภาพ cutscene "พวกเราไม่ได้มาคนเดียว"/"เปิดทางให้ยมบาทน้อย" อยู่แล้ว)
   - แล้ว **ตัดมาที่แผนที่** มีตัวละครยืนบนแผนที่: กำลังเสริมยืนหลังยมบาทฝั่งหนึ่ง · อีกฝั่งมีหัวหน้า 4 คนและบอสโซน 4
   - ผู้เล่นบังคับยมบาทได้อิสระ: เดินไปสู้หัวหน้า 4 โซนเลย / ไปหาพ่อค้านรกซื้อของก่อน / ไปหานิราจัดทีมก่อน / ไปนอนพักที่ศาลาน้ำชาก่อน
   - (ตอนนี้เป็นศึกต่อเนื่อง Wave 1/8 → 8/8 ในหน้าจอเดียว มีหน้าต่าง "ปลดปล่อยหัวหน้าทั้งสี่" ที่คำอธิบายยาวคุณเป้ขีดฆ่าไว้ เพราะไม่ตรงกับแบบใหม่)

## ให้ออกแบบ
1. อ่านโค้ดจริง: โครงสร้างข้อมูลยมทูต/guard/สถิติ, ตัวคูณศัตรูตามโซน, ร้านค้า/ไอเทม, เซฟ (`localStorage` schema + migration), สถานี (room) และ event สุดท้าย (frontier/zoneEvent waves)
2. เสนอ **data model**: ระดับยมทูต (level, exp ต่อมินิเกม), สูตรค่าพลังต่อโซน × ระดับ (โจมตี/พลัง/เติมเลือด) พร้อมตัวเลขตั้งต้นที่ไม่ทำให้สมดุลพัง (เทียบ HP ศัตรูแต่ละโซน), ไอเทมร้านแต่ละโซน (ชื่อ, เติมเท่าไร, ราคา) — ให้เป็นตารางที่ปรับได้ใน `data.js`
3. **minigame framework**: โครงร่วม (เปิดจากสถานี, จำกัดจำนวนครั้ง/วัน-เทิร์นหรือคูลดาวน์ไม่ให้ฟาร์มไม่จบ, คะแนน→exp, ผลลัพธ์) + สเปกสั้นของ 8 มินิเกม (การควบคุม เมาส์/แตะ, เงื่อนไขชนะ, ความยาว 20–60 วินาที) · จัดกลุ่มมินิเกมที่ใช้กลไกร่วมกันได้ (เช่น ยกหิน lan/lokan ใช้ตัวเดียว)
4. **event สุดท้าย**: state machine ใหม่ (wave 1–4 → รางวัลต่อ wave → cutscene กำลังเสริม → map staging โหมดอิสระ → ศึกหัวหน้า 4 คน → บอสโซน 4 → ฉากจบ) · บอกว่าเซฟที่ค้างกลางทางแบบเก่าย้ายเข้าสถานะใหม่อย่างไร
5. แบ่งเป็นใบงาน Codex ตามลำดับ (เช่น G1 = สถิติตามโซน + ร้านค้าตามโซน · G2 = event สุดท้าย · G3 = framework + มินิเกมชุดแรก 3 ตัว · G4 = มินิเกมที่เหลือ) พร้อมไฟล์ที่แต่ละใบแตะ เกณฑ์รับงาน และความเสี่ยง
6. จุดที่ต้องให้คุณเป้ตัดสินใจ (ถ้ามี) — เขียนเป็นคำถามสั้น มีตัวเลือกแนะนำ

## คำขอของคุณเป้ (ตามคำพูด)
- นิรา บุญ มีพลังโล่เพิ่ม เพิ่มพลังโจมตี
- ใน minigame แต่ละที่ ยมฑูตเล่นแล้วจะได้ท่า cutscene เพิ่ม
  - กระทะทองแดง: **เพลิง** ได้ท่าโจมตีไฟใหม่ cutscene เพิ่ม โจมตีแรงขึ้น
  - ประตูสวรรค์: **นิรา บุญ** ได้ท่ารักษา HP มากขึ้น cutscene เพิ่ม
  - ลานตรากตรำ / โลกัณฑ์นรก: **ทัณฑ์ ดำ ยักษ์(ทวารบาล)** ได้ท่าโจมตีใหม่ cutscene เพิ่ม โจมตีแรงขึ้น
  - หอกระจก: **กาญ** ได้ท่าโจมตีใหม่ cutscene เพิ่ม
- ท่าไม้ตายของ **ยามา** มี cooldown: เรียกเพื่อนในทีมมาคอมโบ พุ่งไปโจมตีทีละคน จบด้วยยามาโจมตีหนัก · เพิ่มแถบ cooldown ให้ยามา · ปลดล็อกเมื่อสู้บอสชายแดนโซน 1

## สิ่งที่ต้องอ่านก่อนออกแบบ
ระบบต่อสู้/ท่า/พลังที่มีอยู่: `src/data.js` (POWERS, CREW, BAL), `nira-combat.js`, `crew-power*.js`, `yama-cooldown.js`, `yama-sword*.js`, `weapons.js`, `battle-turns.js`, `battle-dash.js`, `heal-fx.js`, `unlocks.js`, `progression.js`, `training.js`, `src/minigames/`
คิวเดิมที่ทับกัน: ทีม 3→7 คน, ปลดล็อกท่ามินิเกม, ยิงจากมือ, BALANCE-01 (เพิ่มจำนวนศัตรู/ความยากบอสได้เพื่อรับทีมใหญ่) — ออกแบบรวมกัน ไม่แยกระบบซ้ำ
ชื่อ: **ยามา** = ชื่อตัวเอก, "ยมบาทน้อย" = ตำแหน่ง · ผู้ช่วยสะกด **นิรา** · ยมฑูตแต่ละคนมีชื่อตามโซน (`names:{asia,west,cyberhell}` ใน CREW)

## ส่งมอบ (รายงานเดียว ภาษาไทย)
1. **ระบบที่มีอยู่** สรุปสั้น: ท่าของแต่ละคนตอนนี้, ระบบ cooldown/MP, มินิเกมแต่ละแห่งให้อะไรอยู่แล้ว, ชื่อ key สถานี (`krata`, `sawan`, `lan`, `lokan`, `krajok` …)
2. **สเปกท่าใหม่ทุกท่า**: ชื่อไทย, ผู้ใช้, เงื่อนไขปลดล็อก (เล่นมินิเกมกี่ครั้ง/ระดับไหน — เสนอ), ผล (ดาเมจ/ฮีล/โล่/บัฟ ตัวเลข + เป้าหมาย), ต้นทุน (MP/cooldown), ลำดับภาพ (cast → cutscene → impact)
   - โล่และบัฟโจมตีของนิรา/บุญ: ค่าเท่าไร อยู่กี่เทิร์น ซ้อนกันได้ไหม
   - ท่าไม้ตายยามา: กี่คนพุ่ง (ตามจำนวนคนในทีม), ดาเมจต่อคน, ปิดท้าย, cooldown กี่เทิร์น, แถบ cooldown แสดงที่ไหน (อ้าง HUD เดิม), ปลดล็อกจาก flag ไหนในโค้ด (ชนะบอสชายแดนโซน 1 / หลัง farewell?)
3. **สมดุล**: จำลองตัวเลขเทิร์นต่อเทิร์นกับศัตรูชายแดนและบอสแต่ละโซน ก่อน/หลังมีท่าใหม่ ที่ทีม 3, 5, 7 คน — เสนอปรับ HP/จำนวนศัตรูถ้าง่ายเกิน
4. **รายการภาพที่ต้องวาด** (สำหรับ Codex วาด): ต่อท่า — cutscene กี่ภาพ ขนาด px ตามมาตรฐาน cutscene เดิม, sprite/เฟรมเพิ่ม, ไอคอนท่า, กระสุน/impact · ระบุไฟล์ภาพเดิมที่ใช้เป็นแบบ (style reference)
5. **แผนแบ่ง run โค้ด** ให้ Codex (ขอบเขตไฟล์ต่อ run ไม่ให้ทับกัน) และความเสี่ยงต่อเซฟเก่า
6. ข้อที่ต้องให้คุณเป้ตัดสิน (ถ้ามี) แยกไว้ท้ายรายงาน ไม่เกิน 5 ข้อ

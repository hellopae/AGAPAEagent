## 1) จุดที่อันตรายที่สุด — `รอ Kittanate ตัดสินใจ` ไม่ใช่ข้อความ แต่เป็น **ค่าสถานะ**

คำนี้ถูก **เทียบตรง ๆ** 3 ที่ ถ้าแก้ไม่ครบพร้อมกัน หน้าเว็บจะไม่ error แต่จะ **เงียบผิด**:
สถิติ "รอ PAE ตัดสิน" เหลือ 0 และป้ายสถานะกลายเป็นสีกลาง โดยไม่มีใครรู้ว่าพัง

| ที่ | เดิม | ใหม่ |
|---|---|---|
| `index.html:1758` | `MT_STATUS_CLS = { 'รอ Kittanate ตัดสินใจ':'wait', … }` | `MT_WAIT = 'รอ PAE ตัดสินใจ'` แล้วใช้ `{ [MT_WAIT]:'wait', … }` |
| `index.html:1832` | `MEETINGS.filter(m => m.status === 'รอ Kittanate ตัดสินใจ')…` | `MEETINGS.reduce((n,m) => n + mtWaitCount(m), 0)` |
| `meetings.json` | `"status": "รอ Kittanate ตัดสินใจ"` | `"status": "รอ PAE ตัดสินใจ"` |
| `build-meeting.mjs:62,270,446` | สตริงเดียวกันเขียนซ้ำ 3 ที่ | `const STATUS_WAIT = "รอ PAE ตัดสินใจ"` ที่เดียว |

**สิ่งที่ทำเพิ่มนอกเหนือจากการแทนคำ (ตั้งใจ):** ยุบสตริงนี้ให้เหลือ **ตัวแปรเดียวต่อไฟล์** (`MT_WAIT` / `STATUS_WAIT`)
พร้อมคอมเมนต์ที่บอกว่าอีกฝั่งอยู่ไฟล์ไหน — ไม่ได้ทำเพื่อความสวย แต่เพราะงานวันนี้พิสูจน์แล้วว่า
สตริงที่ต้อง "แก้พร้อมกัน 3 ที่" คือกับดักที่รอเกิดครั้งต่อไป ครั้งหน้าคนแก้จะแก้ที่เดียวต่อไฟล์

### ผลพลอยได้: แก้บั๊กเงียบที่มีอยู่ก่อนแล้ว 1 ตัว

ของเดิมนับ "รอตัดสิน" ด้วย `filter(status).reduce(decisions.length)` — ถูกต้องอยู่แล้ว
แต่ตอนย้ายมาเป็น `mtWaitCount(m)` ผมล็อกนิยามไว้ในที่เดียวว่า **นับเฉพาะประชุมที่ยังรออยู่จริง**
(ประชุมที่ `ตัดสินใจแล้ว` ยังมี `decisions` ค้างในไฟล์เสมอ ถ้าเผลอนับด้วย = ตัวเลขหลอกให้ Kittanate เห็นงานค้างที่ไม่มีจริง)
ตอนนี้สถิติหัวแท็บกับการ์ดใน Widgets ใช้ **นิยามเดียวกัน** จึงไม่มีทางเพี้ยนคนละทาง — ทดสอบเคสนี้ไว้แล้ว

### `decisions[].owner` — จาก `"kittanate"` เป็น `"pae"`

ค่านี้ถูกแสดงบนหน้ารายละเอียดจริง (`.mt-dec-owner`) ทั้ง 9 ข้อ ถ้าไม่แก้ หน้าเว็บจะยังมีคำว่า kittanate โผล่อยู่
→ แก้ค่าในไฟล์ + สคริปต์รับ `"pae"` เป็นค่าเจ้าของกิจการ (`OWNER_HUMAN`)
**ตัดค่าเก่าออกไม่ให้รับแล้ว** เพราะ record เดียวที่มีอยู่ย้ายครบแล้ว และถ้ามีคนพิมพ์ค่าเก่ามาอีก ควรได้คำเตือนให้ใช้ค่าใหม่
(เป็นคำเตือน ไม่ใช่ error — ไฟล์เก่ายังเขียนเข้าได้ตามเดิม)

### วิธีแก้ `meetings.json` (ไม่แก้ JSON ด้วยมือตามที่สั่ง)

```bash
# 1) ดัมพ์ record ปัจจุบันเป็น draft แล้วแทนคำทุก string (Kittanate→PAE, kittanate→pae)
node -e '…walk ทุก string ใน record…' > /tmp/pae-rename-draft.json
# 2) ตรวจก่อน
node scripts/build-meeting.mjs validate /tmp/pae-rename-draft.json     # ✅ ผ่าน ไม่มีคำเตือน
# 3) เขียนกลับ
node scripts/build-meeting.mjs add /tmp/pae-rename-draft.json --replace
#    ✅ อัปเดต meeting "2026-07-30-mirofish" · ผู้เข้าร่วม 4 · entries 4 · เห็นต่าง 11 จุด
#    ☁️ เขียน Firestore agents/meetings แล้ว
```

**พิสูจน์ว่าไม่ได้แตะเนื้อหาของ Libby:** เอา `git diff` มาไล่ทีละบรรทัด แล้วเช็กว่าบรรทัดที่เปลี่ยน
ทุกบรรทัด ผ่านสูตร `เดิม.replace(/Kittanate/g,'PAE').replace(/kittanate/g,'pae') === ใหม่`
→ ผ่าน 16/18 บรรทัด · อีก **2 บรรทัดคือ `updatedAt`** (สคริปต์ดันเวลาให้ตามที่ออกแบบไว้)
`createdAt` ไม่อยู่ใน diff เลย = ไม่ถูกดัน ✅ · ตัวเลขคงเดิม: **เห็นต่าง 11 · entries 4 · decisions 9**

## 2) การ์ด Meeting ในแท็บ Widgets

**ตำแหน่ง:** ในกริด `.widget-grid` ต่อจาก `#wWork` ("งานของ Agent") ทันที ตามที่ Kittanate ขอให้อยู่ข้าง ๆ ทีม AGAPAE

**แสดงอะไร (ประชุมล่าสุดใบเดียว):**

```
● MEETING · ล่าสุด                        30 ก.ค. 2569
┌────────────────────────────────────────────────┐
│ MiroFish ใช้ประโยชน์กับ TANAPAT ได้ยังไง          │  ← หัวข้อ (ตัดที่ 2 บรรทัด)
│ [ รอ PAE ตัดสินใจ ]                             │  ← ป้ายสถานะ สีเดียวกับในแท็บ Meeting
│ เห็นต่าง                              11 จุด      │  ← สี --flagged
│ รอ PAE ตัดสิน                          9 ข้อ      │  ← สี --gold
└────────────────────────────────────────────────┘
```

**ทำไมเลือก 2 ตัวเลขนี้** — พื้นที่การ์ดเล็กพอสำหรับข้อมูลชุดเดียว ผมเลือก "เห็นต่างกี่จุด" กับ "รอเขาตัดสินกี่ข้อ"
เพราะสองอย่างนี้คือ**เหตุผลที่ฟีเจอร์ Meeting เกิดขึ้นตั้งแต่แรก**: ทีมไม่เห็นตรงกันตรงไหน และอะไรค้างอยู่ที่ Kittanate
สิ่งที่ **ตัดทิ้ง**: รายชื่อผู้ร่วมประชุม (ซ้ำกับแท็บ Meeting ที่กดเข้าไปเห็นทันที) และข้อสรุป
(`conclusion` ของใบนี้ยาว ~1,900 ตัวอักษร ใส่ไปการ์ดจะสูงกว่าการ์ดอื่นเท่าตัวและกดกริดทั้งแถวเสีย)
วันที่ไปอยู่ที่ `.wup` มุมขวาบนตามแบบการ์ดเดิม ไม่กินบรรทัดในตัวการ์ด

**กดแล้วไปไหน:** `openMeetingFromWidget(0)` → ตั้ง `MEET_SEL` แล้วเรียก `switchView('meeting')`
(สลับแท็บ + `renderMeeting()` + scroll ให้เองอยู่แล้ว ไม่ต้องเขียนซ้ำ) → เปิดหน้ารายละเอียดของใบนั้นตรง ๆ

**ทำตามกติกาเดิมของหน้า:**
- ใช้ `.widget` / `.wh` / `.wdot` / `.wup` / `.w-row` / `.w-sub` / `.w-empty` ของเดิมทั้งหมด
- **ไม่เพิ่มตัวแปรใน `:root` แม้แต่ตัวเดียว** (ยังเป็น 23 ตัวเท่าเดิม — มีเทสต์เช็ก)
- ใช้ `.mt-status` ของแท็บ Meeting ซ้ำ → ป้ายสถานะบนการ์ดกับในแท็บเป็นสีเดียวกันเสมอโดยไม่ต้องดูแล 2 ที่
- การ์ดเป็น **`<button>` จริง** (Tab เข้าถึงได้ + มีกรอบโฟกัส) → ข้างในใช้ `<span>` ล้วน
  เพราะ `<button>` รับได้แค่ phrasing content — `<div>` ข้างในเป็น HTML ที่ไม่ valid
- escape ทุกค่าด้วย `TD_ESC` และ**ไม่ยัด id ลง `onclick`** ใช้ index ของ array เหมือนการ์ดในแท็บ Meeting
- CSS ใหม่ 6 rule ทั้งหมดอยู่ใต้ `.w-meet` (ไม่มี rule ไหนไปแตะ selector เดิม)
- responsive: ไม่ต้องเพิ่ม breakpoint — `.widget-grid` เป็น `auto-fit minmax(280px,1fr)` อยู่แล้ว
  และ `@media(max-width:560px)` เดิมคุม `.widget-grid{gap:12px}` ให้ครบ · หัวข้อ line-height 1.6 ตามกติกาภาษาไทย

**ประชุมมากกว่า 1 ใบ:** เพิ่มบรรทัด `.w-sub` ว่า "อีก N ประชุมก่อนหน้า — ดูทั้งหมดในแท็บ Meeting"
(ตอนนี้มีใบเดียวจึงไม่ขึ้น — ไม่อยากให้การ์ดพูดว่า "อีก 0 ประชุม")

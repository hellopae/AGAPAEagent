### `severity` ควร required หรือ optional — คำตอบ: **optional + default `challenge` + คำเตือน**

- **ไม่ required** เพราะ "แรงแค่ไหน" เป็นการตัดสิน ไม่ใช่ข้อเท็จจริงที่อ่านจากไฟล์ได้ตรง ๆ
  ถ้าบังคับ ผู้กรอกที่ไม่แน่ใจจะเดา แล้วเราจะได้ `blocker` ที่ไม่ใช่ blocker — ซึ่งอันตรายกว่าไม่ระบุ
  (ป้ายที่เตือนพร่ำเพรื่อ = ป้ายที่ไม่มีใครดู)
- **default = `challenge` ไม่ใช่ `note`** เพราะการลืมกรอกไม่ควรทำให้ข้อค้านถูกกลบไปท้ายหน้า
  และไม่ควรทำให้ดูแรงเกินจริงเช่นกัน — ค่ากลางเป็นทางที่ผิดน้อยที่สุดทั้งสองทาง
- **มีคำเตือน (ไม่บล็อก)** ทุกครั้งที่ไม่ระบุ → ตอนรัน Libby เห็นทันทีว่าข้อไหนยังไม่ได้ให้ระดับ
- **แต่ค่าที่พิมพ์ผิดเป็น error ไม่ใช่เตือน** (ต่างจาก `status`/`role` ที่เป็นข้อความอิสระ)
  เพราะ UI ใช้ค่านี้ **เรียงลำดับ** — `"Blocker"` ตัวใหญ่ที่ตกไปเป็น challenge เงียบ ๆ
  จะทำให้ของที่ทำงานพังไปโผล่ล่างสุดโดยไม่มีใครรู้ · `factcheck`/`stance` ใช้กติกาเดียวกัน

### migration ของ record MiroFish

```bash
node scripts/build-meeting.mjs add /tmp/mirofish-migrate.json --replace
# ✅ อัปเดต meeting "2026-07-30-mirofish" (ผู้เข้าร่วม 3 · entries 3 · เห็นต่าง 8 จุด)
```

- **เนื้อหาของ Libby ไม่ถูกแตะแม้แต่ตัวอักษรเดียว** — ย้ายเฉพาะโครงฟิลด์ (สคริปต์ที่ใช้ migrate อ่านค่าเดิมมาวางตรง ๆ)
- `factcheck` ทั้ง 3 entry = **`"passed"`** + `factcheckFile` = `Output/Reese/2026-07-31-mirofish-factcheck.md`
  Reese ให้ verdict "⚠️ ผ่านแบบมีเงื่อนไข" ทั้ง 3 ฉบับ — **ผลของ gate คือ "ผ่าน"** เงื่อนไขคือรายการแก้ย่อย
  ไม่ใช่การตีตก ถ้าใช้ `failed` จะสื่อผิดหนักกว่ามาก (enum มี 3 ค่า ไม่มี "ผ่านแบบมีเงื่อนไข")
  → ทางที่ตรงกว่านี้คือมีฟิลด์ `factcheckNote` ในอนาคต ถ้า Kittanate อยากให้เห็นเงื่อนไขบนหน้าเว็บ
- `createdAt` เดิมไม่ถูกดัน (`2026-07-31T00:33:20Z`) — `--replace` รักษาไว้ตามที่ออกแบบไว้ขั้นที่ 1
- `severity`: ให้ **`blocker` 1 จุด** (Nick → Minnie ข้อแรก) เพราะ**ข้อความของ Libby เองระบุผลไว้ตรง ๆ** ว่า
  *"สมมติฐานที่เป็นฐานของ TOP PICK พังทั้งใบ และ gate ≥7/10 รันไม่ได้"* = เข้านิยาม blocker พอดี
  ไม่ได้เพิ่มข้อมูลใหม่ · ที่เหลือ 7 จุดให้ `challenge`
  *(Vera อ่านไฟล์ต้นทางเองแล้วให้ระดับตรงกัน — ดู fixture §8 ของเธอ)*
  → **แต่ระดับของอีก 7 จุดควรให้ Libby ทวนอีกรอบ** ผมให้ค่ากลางไว้เท่านั้น ไม่ได้อ่านตัดสินทีละข้อ

### รายละเอียดที่ตัดสินเองระหว่างเขียน

- **hero ตอน detail: ซ่อน** (`#meetHero.style.display='none'`) ไม่ใช่สลับข้อความ — Vera ให้เลือกอย่างใดอย่างหนึ่ง
  เลือกซ่อนเพราะ `.mt-d-topic` ทำหน้าที่หัวเรื่องอยู่แล้ว และการสลับข้อความ hero ทำให้มีหัวเรื่อง 2 ระดับซ้อนบนมือถือ
- **การ์ดในหน้ารายการเป็น `<button>`** → ข้างในใช้ `<span>` ทั้งหมด (ไม่ใช้ `<div>`)
  เพราะ `<button>` รับได้แค่ phrasing content — `<div>` ข้างในเป็น HTML ที่ไม่ valid และเบราว์เซอร์บางตัวจัด layout เพี้ยน
- **escape ทุกค่าด้วย `TD_ESC`** ตาม V8 รวมถึงค่าที่เอาไปใส่ `href` — และ**ไม่ยัด id ลง `onclick`**
  ใช้ index ของ array แทน (`openMeetingAt(0)`) เพื่อไม่ให้มีทางที่ string จากไฟล์หลุดเข้า JS context
- **`flash` ของเดิมเป็นวงแหวนสีเขียว** (`--done`) ใช้กับการ์ดความเห็นต่างแล้วสื่อผิด → เพิ่ม `@keyframes mtflash`
  สี `--flagged` แทน (2 บรรทัด ไม่แตะ animation เดิม)
- **`prefers-reduced-motion`** — `scrollIntoView` เช็ก `matchMedia` เองก่อนเลือก `smooth`/`auto`
  (media query ที่มีอยู่ครอบแค่ CSS transition ไม่ครอบ scroll ของ JS)
- **สถิติช่องที่ 3 "รอ Kittanate ตัดสิน" นับ *จำนวนข้อ* ไม่ใช่จำนวนประชุม** — ของ MiroFish = 7

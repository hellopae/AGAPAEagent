## 1. ภาษาออกแบบร่วม (ใช้ทั้งสองหน้า)

### 1.1 สีจากธีมเดิม + สีใหม่ที่ต้องเพิ่ม

ธีมเดิมใน `:root` (index.html บรรทัด ~13-22) มี **ทอง** (`--gold:#d4a355`) กับ **แดงเลือด**
(`--primary:#c2381f`, `--destructive:#e04a2f`) อยู่แล้ว แต่ **ยังไม่มี "ม่วงเข้ม" ที่ชัดพอ**
(`--accent:#3d2029` เป็นน้ำตาลแดงอมม่วงจาง ๆ ไม่พอ) — เพิ่ม 2 ตัวแปรใหม่ใน `:root`:

```css
--hell-purple-1:#241129;   /* ม่วงเข้มเกือบดำ — พื้นหลังกรอบ/แถบเมนู */
--hell-purple-2:#4a1f3d;   /* ม่วงอมแดง — จุดไล่สีสว่างขึ้นของการ์ด/ปุ่ม */
```

### 1.2 กรอบ + พื้นผิว (แทนกล่องดำทึบ) — ใช้กับ `.hud`, `dialog.rpg .arena`, และการ์ดย่อยทุกใบ

**ไม่ต้องมีไฟล์ภาพใหม่ — เขียนด้วย CSS ล้วน:**

- **กรอบนอก:** `border:1.5px solid var(--gold); border-radius:var(--radius)`
- **กรอบในบาง (double-line แบบขอบลายไทย):**
  `box-shadow: inset 0 0 0 1px rgba(212,163,85,.28), inset 0 0 28px rgba(0,0,0,.55)`
- **มุมฉลุ HUD (4 มุม, ใหม่ — `.corner-tick`):** สี่เหลี่ยม 18×18px มุมแต่ละมุมมี border-top/border-left
  (หรือ top/right, bottom/left, bottom/right ตามมุม) หนา 2px สีทอง วางเยื้องเข้ามาจากขอบจริง 6px
  — ได้เอฟเฟกต์ "วงเล็บมุม" แบบ HUD เกม ไม่ต้องพึ่งรูป:
  ```css
  .corner-tick{position:absolute;width:18px;height:18px;pointer-events:none;z-index:5}
  .corner-tick.tl{top:6px;left:6px;border-top:2px solid var(--gold);border-left:2px solid var(--gold)}
  .corner-tick.tr{top:6px;right:6px;border-top:2px solid var(--gold);border-right:2px solid var(--gold)}
  .corner-tick.bl{bottom:6px;left:6px;border-bottom:2px solid var(--gold);border-left:2px solid var(--gold)}
  .corner-tick.br{bottom:6px;right:6px;border-bottom:2px solid var(--gold);border-right:2px solid var(--gold)}
  ```
  ใส่ 4 อันนี้เป็นลูกโดยตรงของ `.hud` และของ `.arena` (z-index สูงกว่า scrim แต่ต่ำกว่าปุ่ม)
- **พื้นหลังกรอบใหญ่:** แทน `#221324` ทึบเดิม ด้วย
  `linear-gradient(165deg, var(--hell-purple-1) 0%, #1a0a12 55%, var(--background) 100%)`
  (ไล่ม่วงเข้ม → เกือบดำ แทนสีเดียวแบน ๆ)
- **การ์ดย่อยทุกใบ** (`.hud-card`, `.port`, ปุ่มเมนู, `.plate`): แทน `rgba(12,6,9,.86)` เรียบ ๆ ด้วย
  `linear-gradient(180deg, rgba(74,31,61,.55) 0%, rgba(20,10,14,.92) 100%)` +
  `border:1px solid var(--border)` + เส้นไฮไลต์บนขอบบน 1px `rgba(255,255,255,.05)` (bevel เบา ๆ)
- **`.orn` (ลายกนกเปลวไฟทองที่มีอยู่แล้วในหน้าปก, index.html บรรทัด ~948-953):** เอามาวางเป็นครีบเล็ก ๆ
  กึ่งกลางด้านบนของ `.hud`/`.arena` (เหนือ `.hud-top`) ขนาด ~36px กว้าง โปร่งแสง .55 — เป็นของตกแต่ง
  **ทำได้ถ้ามีเวลา ไม่ใช่ของบังคับ** (ดูหัวข้อ 6)

### 1.3 คอมโพเนนต์ปุ่มมาตรฐานใหม่ (ใช้ทั้งเมนูบาร์สอบสวน + ปุ่ม acts ต่อสู้) — เรียก `.hud-btn`

## 2. หมายเหตุการอ่านตัวเลขในเอกสารนี้

- **Desktop 1440** = สมมติวินโดว์ 1440×900 (`100dvh`≈900) ตัวเลขปัดเป็นค่าจริงที่เกิดขึ้นจริง
- **390×844 / 360×640** = วัดจากความกว้าง/สูงจริงของอุปกรณ์ ลบ margin ของ `dialog.hudwrap` มือถือที่มีอยู่แล้ว (`calc(100dvh - 12px)`, `calc(100% - 12px)`)
- เกณฑ์ "ไม่ต้องเลื่อนอ่าน" (ข้อ 3 ของคุณเป้) หมายถึง **บล็อกสำนวน (`.hud-rec`) ต้องเห็นครบไม่มีสกอลล์ภายในตัวมันเองในทุกจอ** — ส่วน `.hud-opt` (ตัวเลือกที่กด) กับ `.hud-log` (บันทึกสอบสวน) อนุญาตให้มีสกอลล์ภายในตัวเองได้ถ้าเนื้อหายาวเกิน (เช่นคดีมีตัวเลือกจี้เยอะ, log สะสมหลายบรรทัด) เพราะเป็นคนละเกณฑ์กับ "อ่านสำนวนไม่ได้" — แต่ **ตัวกล่องเองต้องมองเห็นอยู่บนจอเสมอ ไม่ใช่ต้องเลื่อนทั้งโมดัลลงไปหา**

เพราะเป็นปุ่มปิดคดี — นี่คือกฎเดียวที่ต่างจากการ "เลื่อนหาปุ่ม" (ซึ่งคนละเรื่องกับ "เลื่อนอ่านสำนวน" ที่ห้าม)

### 3.6 ตำแหน่ง `.hud-stage` (ตัวละครกลางจอ) — ปรับเล็กน้อยให้สมดุลกับพื้นที่ที่ได้คืนมา

เดิม `.hud .fig img{height:clamp(110px,26vh,196px)}` — ปรับเป็น:

| | เดิม | ใหม่ |
|---|---|---|
| Desktop 1440 | 196px (cap) | **clamp(150px, 32vh, 230px)** |
| 390×844 (`≤900` bucket) | `.hud-stage{height:180px}` | **`.hud-stage{height:190px}`**, img `clamp(130px,24vh,180px)` |
| 360×640 (`≤520` bucket) | `.hud-stage{height:270px}` (เดิมสูงเกินจำเป็นบนจอเตี้ย 640) | **`.hud-stage{height:150px}`** (ลดลงเพื่อคืนพื้นที่ให้ `.hud-rec`/`.hud-opt`), img `clamp(110px,20vh,150px)` |

## 5. รายการภาพที่ต้องวาดเพิ่ม

**ไม่ต้องวาดภาพใหม่เลยสำหรับของที่ "ต้องทำ"** — กรอบ/มุมฉลุ/พื้นผิวไล่สีทั้งหมดในหัวข้อ 1 ทำด้วย CSS gradient
+ box-shadow + `.orn` SVG ที่มีอยู่แล้ว (index.html บรรทัด ~948) สอดคล้องกับงบภาพของเกมที่ล็อกไว้ใน `CONCEPT.md`
(เพดาน 50MB, ปัจจุบันใช้ไป 24MB) — งานนี้ **ไม่เพิ่มภาระโหลดเลยสักไบต์**

**ทำได้ถ้ามีเวลา (ไม่บังคับ) — ให้ Mind เขียน prompt ต่อถ้าคุณเป้าไฟเขียว:**

| ไฟล์ที่เสนอ | ใช้ตรงไหน | ขนาด px |
|---|---|---|
| `img/tex-paper-hell.png` | พื้นผิวกระดาษ/หนังสัตว์เก่า ๆ ไว้เป็น `background-image` ของ `.hud-rec` (สำนวน) แทนพื้นเรียบ ให้ความรู้สึก "แฟ้มคดี" มากขึ้น — ต้อง tileable, โทนสีน้ำตาลไหม้เข้ากับกรอบทอง | 256×256, tileable, ไฟล์ < 80KB |

ไม่มีรายการอื่นนอกจากนี้ — ตัวละคร/ฉากหลังที่ใช้อยู่ (hero-yama, spirit*, BG-Turn-Base.webp) ใช้ของเดิมทั้งหมด

## 6. ต้องทำ vs ทำได้ถ้ามีเวลา

**ต้องทำ (ครบ 5 คำสั่งของคุณเป้ ขาดไม่ได้):**
1. ย้าย `.hud-left` → `.hud-menu` แนวนอน (หัวข้อ 3.1, 3.5)
2. ขยาย `.port img` ตามตาราง 3.4
3. ตัวเลขจริง `.hud-rec`/`.hud-opt`/`.hud-log` ตามตาราง 3.3 (ไม่สกอลล์ที่สำนวน) + media query แยกความสูงจอที่ 3.6
4. กรอบทอง 2 ชั้น + `.corner-tick` 4 มุม + พื้นหลังไล่สีม่วง-ดำ (หัวข้อ 1.2) ทั้ง `.hud` และ `.arena`
5. ปุ่ม `.hud-btn` ใช้ร่วมกันทั้งเมนูบาร์สอบสวนและ `.acts` ต่อสู้ (หัวข้อ 1.3, 4.3)
6. ขยายตัวละครในฉากต่อสู้ตามตาราง 4.2

**ทำได้ถ้ามีเวลา (ไม่กระทบเกณฑ์รับงาน):**
- ครีบ `.orn` กึ่งกลางด้านบนของกรอบ (หัวข้อ 1.2 ท้ายข้อ)
- พื้นผิวกระดาษ `tex-paper-hell.png` (หัวข้อ 5)
- ปรับ stop สี `.hud-scrim` ให้เนียนขึ้นหลังเพิ่มแถวเมนู (ปัจจุบันคำนวณจากโครงเดิม 4 แถว ตอนนี้เป็น 5 แถว อาจต้องขยับ % จุดมืดเล็กน้อยด้วยตา ไม่มีตัวเลขตายตัว)

## 7. ข้อควรระวังสำหรับ Toby

- ทุกจุดที่ระบุ selector (`.hud-menu`, `.hud-rec`, `.port`, `.arena .fig`, `.hud-btn`, `.corner-tick`) แก้ที่
  `<style>` ใน `AVEGEE/index.html` — โครง HTML ของ `.hud-menu`/`.hud-bottom` แก้ที่ template string ใน
  `openTrial()` (`AVEGEE/src/ui.js` บรรทัด ~1341-1401) และ `arena()` (บรรทัด ~1213-1252)
- **ห้ามเปลี่ยนลำดับ logic**: `trialCmd`, `pick.st/cr/inten`, `g.needBattle()`, `dests`/`idle`/`heaven` ทั้งหมดคงไว้
  ทุกตัว — งานนี้ย้ายแค่ตำแหน่ง HTML/CSS ของปุ่มที่ผูกกับตัวแปรเดิม ไม่ใช่เขียนตรรกะใหม่
- ปุ่ม `#t-go`, `#t-skip`, `#t-jail`, `[data-cmd]`, `[data-pickkey]` ต้อง**คง `id`/`data-*` เดิมทุกตัว** เพราะ
  `onclick` ผูกไว้ที่ query selector เหล่านี้ (ดูบรรทัด ~1406-1436) ย้ายแค่ตำแหน่งในโครง ไม่เปลี่ยนชื่อ attribute
- ทดสอบตามที่คอมเมนต์เดิมเตือนไว้ (index.html บรรทัด ~607-611): ต้องเช็คว่า `.hud`/`dialog.hudwrap` ไม่หดเหลือ
  แคบ ๆ หลังกดปุ่มสลับ `trialCmd` (บั๊กเดิมเคยเจอ 17 ก.ย.) — คง `min-width:min(1320px,calc(100% - 32px))` ไว้
  (ปรับเลขจาก 1180 → 1320 ตามหัวข้อ 3.2)
- จอ 360×640 คือจอที่ตึงที่สุด — ทดสอบจอนี้ก่อนจออื่นเสมอ เพราะ `.hud-stage` เดิมสูง 270px ที่ breakpoint
  `≤520px` กินพื้นที่จนสำนวนต้องสกอลล์ (สาเหตุที่คุณเป้บ่นเรื่อง "ต้องเลื่อนไปมา") ต้องลดเหลือ 150px ตามหัวข้อ 3.6
  ไม่ใช่แค่ลดฟอนต์อย่างเดียว

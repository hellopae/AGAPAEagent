# Skill: skill-harvest

> hook `scripts/hook-skill.mjs` เรียกเกณฑ์ในไฟล์นี้ตอนจบเทิร์นที่ทำงานใหญ่ (ถามครั้งเดียวต่อ session)
> เป้าหมาย: ระบบต้องเก่งขึ้นเองจากงานที่ทำ ไม่ใช่รอ Kittanate สั่งเขียนคู่มือทีละครั้ง

## ขั้นที่ 1 — ตัดสินก่อนว่าเก็บหรือไม่เก็บ (อย่าเขียนมั่ว)

**เก็บเป็น skill เมื่อเข้าอย่างน้อย 1 ข้อ**

- มี **ลำดับขั้นที่ทำผิดลำดับแล้วพัง** — ต้องมีคนบอกว่าอะไรก่อนอะไร
- เพิ่ง **เสียเวลาไปกับกับดัก** ที่ถ้ารู้ก่อนจะไม่เสีย (พลาดแล้วแก้แพง)
- เป็น **งานที่จะเกิดอีกแน่ๆ** (เวปหน้าถัดไป, บทความชิ้นถัดไป, deploy ครั้งหน้า)
- มี **ค่า/สเปคที่ต้องตรงเป๊ะ** และจำเองแล้วมักพิมพ์ผิด

**ไม่ต้องเก็บ — เอาไปที่อื่นแทน**

| สิ่งที่ได้จากงาน | ที่เก็บที่ถูกต้อง |
|---|---|
| ผลลัพธ์/ข้อมูล/ตัวเลขของงานชิ้นนั้น | `Output/<Agent>/` + worklog |
| งานครั้งเดียวจบ ไม่เกิดซ้ำ | ไม่ต้องเก็บ |
| ความชอบ/การตัดสินใจของ Kittanate | memory (`~/.claude/projects/.../memory/`) |
| กฎที่ต้องบังคับทุกครั้งจริงๆ ห้ามลืม | hook ใน `scripts/` (โค้ดบังคับ ไม่ใช่คำเตือน) |
| เรื่องที่ skill เดิมพูดถึงอยู่แล้ว | **อัปเดต skill เดิม** อย่าสร้างใหม่ซ้อน |

⛔ **ห้ามสร้าง skill ใหม่ก่อนเช็คของเดิม** — `ls .claude/skills/` ทุกครั้ง ถ้าเรื่องใกล้กันให้แก้ของเดิม
ระบบพังเพราะมี skill 30 ตัวที่ทับกัน ไม่ใช่เพราะมี 8 ตัวที่ชัดเจน

## ขั้นที่ 2 — เขียน

ที่ `.claude/skills/<ชื่อ-kebab-case>/SKILL.md` รูปแบบเดียวกับของเดิมทุกตัว

```markdown
---
name: <ชื่อ-kebab-case>
description: <ทำอะไร> — ใช้เมื่อ <trigger ที่เป็นรูปธรรม เขียนคำที่คนจะพิมพ์จริง>
---

# Skill: <ชื่อ>

> แหล่งอ้างอิงเต็ม: <path ไป SOP/ไฟล์จริง ถ้ามี>

## <ขั้นตอน หรือ กติกา>
...
```

กติกาการเขียน:
- **`description` คือทั้งหมดที่ตัดสินว่า skill จะถูกเรียกไหม** — ใส่คำที่จะเจอจริงในงาน (ชื่อโปรเจกต์, ชื่อเครื่องมือ, อาการของปัญหา) ไม่ใช่คำสวยๆ
- เขียนเฉพาะสิ่งที่ **ทำให้ตัดสินใจต่างออกไป** — ตัดคำอธิบายทั่วไปที่โมเดลรู้อยู่แล้วทิ้ง
- ทุกคำสั่ง/ค่า ต้อง **ตรวจแล้วว่าใช้ได้จริง** ห้ามใส่จากความจำ
- ยาวไม่เกิน ~80 บรรทัด — ถ้ายาวกว่านั้นแปลว่าควรเป็น SOP แล้วให้ skill ชี้ไปหา
- มีหัวข้อ "กับดัก" หรือ "ปิดงาน" เสมอถ้าเป็น workflow

## ขั้นที่ 3 — ต่อสายให้ระบบเห็น

1. เพิ่มชื่อ skill ในรายการข้อ 4 ของ `CLAUDE.md`
2. ถ้าเกี่ยวกับ SOP ตัวไหน ให้ SOP นั้นชี้กลับมาที่ skill ด้วย
3. commit + push (DoD ข้อ 5)

## ขั้นที่ 4 — รายงาน

บอก Kittanate 1 บรรทัดว่าเก็บอะไรไว้และจะช่วยตอนไหน
ถ้าตัดสินใจ **ไม่เก็บ** ก็บอกสั้นๆ ว่าทำไม แล้วจบเทิร์นได้เลย — hook ไม่ถามซ้ำใน session เดิม

## ⚠️ กฎเหล็ก 5 ข้อ

1. **ห้าม `git commit` / `git push` และห้ามแก้ไฟล์ในรีโป** — cloud routine push ขึ้น git ไม่สำเร็จ (บทเรียนจาก routine Manga 6 ส.ค. 2569) รีโปมีไว้ให้ **อ่าน** อย่างเดียว ช่องทางส่งมอบจริงคือ Firestore
2. **ห้ามใส่ตัวเลขต้นทุน/ราคาของโรงพิมพ์ทุกรูปแบบ** — บาท เปอร์เซ็นต์ สัดส่วน หรือ "แพงกว่ากี่เท่า" Kittanate สั่งห้ามเอง เพราะเสียเปรียบตอนคิดราคากับลูกค้า เรื่องราคาพูดได้แค่ **ลำดับถูก→แพง** ไม่มีตัวเลขกำกับ
3. **ห้ามพูดเรื่อง outsource / อะไรทำเองอะไรส่งต่อ** — SME ส่งงานเฉพาะทางต่อเป็นเรื่องปกติของวงการ หยิบมาเขียนเท่ากับสร้างประเด็นที่ไม่มีใครสงสัย
4. **เป้าหมายของบทความคือดึงคนเข้าเว็บและเพิ่มยอดสั่งซื้อ** ไม่ใช่ความโปร่งใสหรือเปิดหลังบ้าน — ต้องเป็นความรู้ทั่วไปที่คนค้นหาจริง
5. **ทุกหัวข้อใหม่ตั้ง `status` เป็น `"idea"`** — เป้ยังไม่ได้เลือก

## วันที่และคลังเดิม
อ่านวันจริงด้วย `TZ=Asia/Bangkok date '+%Y-%m-%d %A %H:%M'` แล้วคำนวณ ISO week และวันจันทร์–อาทิตย์โดยใช้ Asia/Bangkok เสมอ (ไม่ใช้ timezone default ของ Python)
WEEK = YYYY-Www, WEEK_THAI = ช่วงวันจันทร์–อาทิตย์แบบไทย ปี พ.ศ. = ค.ศ. + 543
อ่าน payload เดิมตาม common.md; ใช้ article.json เป็นฐานได้เฉพาะ snapshot 404 เท่านั้น
อ่าน entries เดิมอย่างน้อย 80 หัวข้อแรก ห้ามเสนอซ้ำ; อ่าน CONTEXT.md และ SOP/SOP-02-content-article.md เป็นบริบทเรื่องเนื้อหา
ถ้ามีหัวข้อของสัปดาห์นี้บางส่วน ให้รักษา id/เนื้อหา/สถานะที่คุณเป้เลือกแล้ว เติมเฉพาะที่ขาดให้ครบ 3 ห้ามแทนรายการที่เลือกแล้ว

## STEP 2 — เลือก 3 หัวข้อใหม่

### หมวดที่หมุนใช้ได้
เลือกกระดาษ · เตรียมไฟล์ · เทคนิคการพิมพ์ · งานหลังพิมพ์ (เคลือบ ปั๊ม ไดคัท เข้าเล่ม) · บรรจุภัณฑ์ · งานบุญ/พิธี · แบรนด์ดิ้งสำหรับ SME · ศัพท์โรงพิมพ์ที่ลูกค้าไม่เข้าใจ

**กติกาความหลากหลาย:** 3 หัวข้อต่อสัปดาห์ต้องมาจาก **หมวดต่างกันอย่างน้อย 2 หมวด** ห้ามซ้ำหมวดกันทั้ง 3

### เกณฑ์คัดว่าหัวข้อไหน "ดีพอ"
- **คนค้นหาจริง** — ใช้ web search ของ Codex เช็คว่ามีคนถามเรื่องนี้จริงไหม (Pantip, กลุ่ม Facebook, รีวิว, กระทู้ถาม-ตอบ) ไม่ใช่หัวข้อที่นึกเอาเอง
- **ตอบได้ด้วยความรู้ทั่วไป** ไม่ต้องเปิดตัวเลขต้นทุนของ TANAPAT
- **จบแล้วลูกค้าอยากขอใบเสนอราคา** — ไม่ใช่คำนวณเองได้จนไม่ต้องถามเรา
- **เขียนได้จริงใน 800–1200 คำ** ไม่กว้างจนต้องแตกเป็นซีรีส์

### ข้อควรระวังเรื่องข้อเท็จจริง
- **HIKOTE และ GB (สามเหรียญ) เป็นชื่อแบรนด์ของอาร์ตการ์ดเคลือบ 2 หน้า (C2S) ไม่ใช่ชนิดกระดาษ** — ห้ามสลับสองอย่างนี้
- ตัวเลขที่ใส่ในโครงเรื่องได้มีแค่ตัวเลขสาธารณะที่อ้างอิงแหล่งได้ (ค่าแกรมจาก spec sheet ขนาดกระดาษมาตรฐาน จำนวนหน้าหาร 4 ลงตัว) ที่เหลือห้าม


## Schema และส่งมอบ
โครงสร้าง entry ใหม่ทุก key ต้องครบ:
```json
{
  "id": "art-<WEEK ไม่มีขีด เช่น 2026W36>-<01|02|03>",
  "week": "<WEEK เช่น 2026-W36>",
  "date": "<YYYY-MM-DD ของวันจันทร์สัปดาห์นี้>",
  "displayDate": "<WEEK_THAI>",
  "category": "<หมวด สั้น ๆ ไม่เกิน 20 ตัวอักษร>",
  "title": "<หัวข้อบทความ 1 บรรทัด ไม่เกิน 70 ตัวอักษร ต้องอ่านแล้วอยากคลิก>",
  "hook": "<ประโยคเปิดที่ทำให้คนอ่านต่อ 1 ประโยค ห้ามใส่เครื่องหมายคำพูดซ้อนข้างใน>",
  "audience": "<เขียนให้ใครอ่าน เจาะจง ไม่ใช่ 'คนทั่วไป'>",
  "why": "<ทำไมหัวข้อนี้ดึง traffic/ยอดสั่งซื้อ อ้างสิ่งที่ค้นเจอจริง>",
  "outline": ["<หัวข้อย่อย 5-7 ข้อ เรียงตามลำดับที่จะเขียน>"],
  "keywords": ["<คีย์เวิร์ดที่คนน่าจะพิมพ์ค้น 3-5 คำ>"],
  "channel": "เว็บ TANAPAT + Facebook เพจ",
  "status": "idea"
}
```


ตรวจครบ 3 หัวข้อในสัปดาห์นี้, outline 5–7 ข้อ, keywords 3–5 คำ; status ของรายการใหม่เป็น idea
รวมรายการสัปดาห์นี้ไว้บนสุด ตามด้วย entries เก่าที่ id ไม่ซ้ำ จำกัด 300 รายการ รักษา note เดิม
payload `dataJson` = JSON string ของ `{updatedAt: nowUTC, note: old.note || "", entries: [...]}`
fields ปลายทาง: title="หัวข้อบทความสัปดาห์นี้", date=WEEK_THAI, items=[3 titles], dataJson, updatedAt=nowUTC, checkedAt=nowUTC, source="codex-fallback"
ใช้ writer ใน common.md ส่ง agents/article พร้อม snapshot เดิม ห้าม retry เมื่อเขียนล้ม (แทนกฎ retry 1 ครั้งของ Claude เพื่อรักษา precondition)
อ่านกลับแล้วรายงาน WEEK_THAI + หมวดและหัวข้อทั้ง 3 + ผล sync ไม่เขียนบทความเต็ม ไม่ส่งอีเมล
